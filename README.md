### Leela — исходный код для самостоятельного размещения

Этот архив содержит экспорт текущего приложения: страницы, серверные маршруты, компоненты, стили, настройки, изображения поля, иконки, локальные шрифты и исходные описания 72 клеток. Работающий сайт не изменялся при подготовке архива. Версия для переноса больше не обращается к API или CDN Abacus AI.

**Важно:** это исходники, а не резервная копия базы данных. Аккаунты, хеши паролей, сохранённые игры, заметки и отредактированные в админке описания клеток не включены. Для существующих данных нужен отдельный перенос базы. Секреты, служебные ключи хостинга, кэш сборки и зависимости `node_modules` намеренно исключены.

### Стек и версии

Приложение создано на платформе Abacus AI; эта экспортная версия рассчитана на отдельный Node.js-сервер или Vercel. Интерфейс — React 19.2.8 и TypeScript 5.6.3; стили — Tailwind CSS 3.4.0, Radix UI и Lucide. Анимации — Framer Motion. Авторизация — Auth.js (`next-auth` 5.0.0-beta.32), JWT и bcryptjs. Доступ к данным — Prisma 6.7.0, тип базы указан в `prisma/schema.prisma`. PDF — PDFKit 0.17.2 с локально встроенным шрифтом и поддержкой кириллицы.

Точные версии серверного пакета и всех библиотек закреплены в `package.json` и `yarn.lock`. Это серверное приложение: его нельзя загрузить как статическую страницу на GitHub Pages.

**Проверенная локальная версия Node.js: 22.23.4.** Она записана в `.nvmrc` и `.node-version`. Менеджер пакетов — **Yarn 4.13.0**, закреплён в `packageManager`. В Vercel используется ветка **22.x** из `engines.node`; платформа самостоятельно выбирает актуальное исправление этой ветки и не обещает ту же patch-версию, что на локальном компьютере.

### Локальный запуск с новой базой

Распакуйте архив на своём компьютере и откройте терминал в папке `leela`, где находится `package.json`.

Если используете nvm (macOS/Linux):

```bash
nvm install
nvm use
corepack enable
corepack yarn --version
corepack yarn install
```

На Windows установите Node.js 22.23.4, затем выполните последние три команды. Используйте Yarn, не смешивайте разные менеджеры зависимостей. `postinstall` автоматически создаёт клиент базы данных и не изменяет таблицы.

Создайте локальный файл конфигурации:

```bash
cp .env.example .env
```

В PowerShell аналогичная команда — `Copy-Item .env.example .env`. Заполните `DATABASE_URL` строкой подключения из панели **вашей новой базы**. Тип базы должен соответствовать `provider` в `prisma/schema.prisma`. Рекомендуется отдельная база для разработки. Не используйте рабочую базу как площадку для тестирования.

Создайте секрет на своём компьютере:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Скопируйте результат в `AUTH_SECRET` внутри `.env`. Не отправляйте его в чат, репозиторий или скриншоты. `NEXTAUTH_SECRET` можно оставить пустым; если он используется одновременно с `AUTH_SECRET`, задайте одинаковые значения. Для локального запуска оставьте `NEXTAUTH_URL=http://localhost:3000`.

**Только для новой пустой базы** создайте таблицы и наполните клетки:

```bash
corepack yarn db:push
corepack yarn db:seed
corepack yarn dev
```

Откройте `http://localhost:3000` на своём компьютере. Для входа требуется аккаунт. Публичная регистрация создаёт обычного пользователя, ожидающего одобрения.

### Создание первого владельца

Перед `yarn db:seed` заполните в локальном `.env` поля `OWNER_EMAIL`, `OWNER_NAME` и `OWNER_PASSWORD`. По умолчанию email — `admin@mail.ru`, но **пароля по умолчанию нет**. Укажите свой пароль длиной от 12 символов, не более 72 байтов UTF-8.

Запустите `corepack yarn db:seed`. Скрипт создаст владельца только при отсутствии такого аккаунта. Существующие пароли, права и описания клеток не перезаписываются. После выполнения удалите `OWNER_PASSWORD` из окружения. Не добавляйте эту переменную в Vercel.

Если аккаунт уже существует и вы сознательно хотите назначить его владельцем, укажите `PROMOTE_GAME_OWNER=true`, правильный `OWNER_EMAIL`, запустите `corepack yarn db:seed` и верните флаг в `false`. Эта операция не меняет пароль. Не выполняйте её случайно против чужой или рабочей базы.

### Проверка и production-сборка

```bash
corepack yarn typecheck
corepack yarn build
corepack yarn start
```

`build` создаёт production-версию в `.next`, `start` запускает её на порту 3000. Для остановки нажмите Ctrl+C. Полноценный вход и игра требуют настроенной базы. Дополнительный статический анализ — `corepack yarn lint`; предупреждения и результаты проверки описаны отдельно в `VERIFICATION.md`.

Локальные проверочные скрипты из `scripts/verify-*` сохранены как часть исходников. Они могут создавать и удалять свои тестовые записи; запускайте их только против отдельной тестовой базы. Браузерные Python-проверки требуют дополнительных инструментов и не нужны ни для сборки, ни для Vercel. Исторические визуальные проверки могут описывать предыдущую версию интерфейса. Не выдавайте их запуск за актуальную полную проверку дизайна.

### Загрузка в GitHub

Архив содержит оригинальное изображение поля и закрытые описания. **Создайте приватный репозиторий**, чтобы не раскрыть эти материалы всем посетителям GitHub. Защита в интерфейсе сайта не защищает содержимое публичного репозитория.

На GitHub нажмите **New repository**, выберите **Private** и создайте пустой репозиторий. На своём компьютере, в распакованной папке `leela`, выполните:

```bash
git init
git add .
git status
git commit -m "Экспорт Leela"
git branch -M main
git remote add origin <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

В команде замените `<URL_ВАШЕГО_РЕПОЗИТОРИЯ>` на адрес приватного репозитория, указанный GitHub. Эти действия предназначены **только для распакованной копии на вашем компьютере**, не для управляемого проекта Abacus. Перед commit убедитесь, что `.env` и `node_modules` отсутствуют в `git status`. Авторизуйтесь штатным способом GitHub; не вставляйте токены или пароли в URL репозитория.

### Размещение в Vercel

1. Войдите в Vercel и нажмите **Add New → Project → Import Git Repository**.
2. Выберите приватный репозиторий. При необходимости разрешите Vercel доступ только к нему.
3. **Root Directory** — папка с `package.json` (корень репозитория при загрузке содержимого `leela`). Оставьте автоматически определённый тип приложения. Output Directory вручную не меняйте.
4. **Node.js Version** — 22.x. Команды уже заданы в `vercel.json`: установка `corepack yarn install`, сборка `corepack yarn build`.
5. В **Environment Variables** добавьте `DATABASE_URL`, `AUTH_SECRET`, `NEXTAUTH_URL` для нужной среды. Последняя переменная должна содержать адрес именно вашего проекта Vercel, без `/login` в конце. Не копируйте локальный `localhost` в production.
6. До первого рабочего входа создайте таблицы в новой базе и владельца локальными командами из предыдущих разделов. Миграции и seed намеренно **не запускаются автоматически при каждой сборке**.
7. Нажмите **Deploy**. Если окончательный адрес проекта стал известен после первого развёртывания, обновите `NEXTAUTH_URL` в настройках и выполните **Redeploy**.
8. Проверьте вход владельца, одобрение обычного участника, создание игры, сохранение хода, повторное открытие пути и скачивание личного PDF. Для Preview лучше использовать отдельную тестовую базу и отдельные значения переменных.

Клиент базы создаётся командой `postinstall`. Закрытое поле и PDF-шрифт включаются в серверные функции через `outputFileTracingIncludes`. Изображение поля не переносите в `public`: оно должно оставаться доступным только после проверки авторизации.

Документация версии Node.js в Vercel: https://vercel.com/docs/functions/runtimes/node-js/node-js-versions

### Перенос существующих данных

Для нового независимого сайта подготовьте новую базу и отдельный секрет сессий. Старые сессии не переносятся — пользователи войдут заново. Чтобы сохранить аккаунты, права, игры, заметки и текущие описания клеток, экспортируйте данные рабочего приложения через вкладку **Database → Export Data → As Tar Archive** и перенесите их в новую базу с сохранением идентификаторов и связей. Формат архива сначала нужно проверить; данный ZIP не содержит универсального автоматического импортёра.

Не запускайте `db:push` без проверки против базы с важными существующими данными. Никогда не применяйте `--accept-data-loss` или `--force-reset` для такого переноса. Скрипт наполнения добавляет отсутствующие клетки, но не заменяет реальные описания из базы.

### Автономность, пути и отличия экспорта

Все используемые приложением изображения и шрифты включены локально. URL вида `/fonts/...`, `/favicon.svg` и `/api/board` относятся к текущему сайту и не содержат имя внешнего хоста. Импорты `@/...` — локальный алиас из `tsconfig.json`. Файлы сервера находятся относительно корня приложения через `process.cwd()`, без путей исходной виртуальной машины.

Удалены внешняя вставка хостинга, сбор телеметрии исходной платформы и обращение к её PDF API. Локальные библиотеки визуализации сохранены; имя папки `abacus-viz` — только название локальных файлов, не сетевая зависимость. Демо-материалы в `components/viz/examples` не являются страницами игры; их изображения также включены в архив.

PDF-дневник формируется PDFKit внутри серверного процесса. Сохраняется выбор одного участника, его запрос, ходы и заметки, проверка прав и краткосрочный подписанный токен. Оформление PDF отличается от прежнего HTML-рендера: это текстовая многостраничная вёрстка без прежних карточек и фоновых панелей. Длинные документы ограничены памятью, временем функции и допустимым размером ответа выбранного хостинга.

Для работы не нужны ключи Abacus AI или платный PDF-сервис. Интернет нужен при установке пакетов, а работающий сайт подключается к вашей базе. Это не офлайн-приложение: сервер и база необходимы.

Права и ограничения пользователей в интерфейсе сохранены. Ограничение копирования и печати не является гарантированным запретом системных снимков экрана или фотографирования.

### Переменные окружения

Полный шаблон с пояснениями — `.env.example`. Исходный проект использовал `DATABASE_URL`, `AUTH_SECRET`, `NEXTAUTH_SECRET`, `ABACUSAI_API_KEY`; также читал `NEXTAUTH_URL`, `PROMOTE_GAME_OWNER`, служебные `NEXT_DIST_DIR`, `NEXT_OUTPUT_MODE`, `NODE_ENV`, `PORT` и переменные локальных тестов. В экспорте `ABACUSAI_API_KEY`, `NEXT_DIST_DIR` и `NEXT_OUTPUT_MODE` больше не нужны. Добавлены только настройки безопасного ручного создания первого владельца. Действительные значения исходного окружения не входят в архив.
